# AltC comparison tests

`compare_test.go` compiles every `c/*.c` with gcc (`-O0 -w`) and with AltC,
runs both binaries and compares stdout+stderr and the exit code. gcc only
compiles (with the built-in C library's headers, see `gcc_test.go`); AltC's
linker links both programs with the built-in C library.

`libc_test.go` builds the C library with gcc too and runs the programs of
`libc/` (gcc and AltC builds) with both libraries: the output must be the
same. `ALTC_TEST_KEEP=dir` keeps the files of the tests in `dir`.

    go test ./tests/ -run TestCompareWithGCC            # all
    ONLY=name go test ./tests/ -run TestCompareWithGCC -v  # one file

A first-lines comment `// std: c99` selects the `-std=` for both compilers
(use `gnu89` rather than `c89`: gcc rejects `//` comments in strict C90).

## Conventions for test programs

* Deterministic output only: no addresses, time, uninitialized reads or UB.
  Watch out for unspecified argument evaluation order
  (`printf("%d %d", f(&x), x)` differs between compilers) and unsequenced
  modifications (`a[i++] + a[i]`).
* `bug_<topic>.c` files are minimized reproducers of AltC bugs; each has a
  comment with the expected output. They stay in the suite as regression tests.
* `*_matrix.c` files (conv_matrix, ops_matrix, fops_matrix) were generated by
  small Python scripts: every case is evaluated at run time (volatile
  operands), by constant folding, and in a static initializer.

## Known limitations (intentional, not tracked as bugs)

* `__float128`/`_Float128`, `_BitInt`
* GNU nested functions
